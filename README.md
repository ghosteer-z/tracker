# Tracker

这是一个“人物完整访谈”检索项目。当前只建设第一步：确定收录规则，并用一个极简清单保存结果。

## 这一阶段解决什么问题

每一行数据只代表一场真实发生的访谈。我们不保存转载、不为同一场访谈建立多个媒体资产，也暂时不做网页和数据库。

一场访谈只保留一个最佳来源，优先顺序是：

1. 原始发布方提供的完整文字底稿；
2. 原始发布方提供的完整视频；
3. 原始发布方提供的完整音频。

以后找到更优来源时，直接替换原记录中的 `source`，不新增一条记录。

## 什么可以收录

- 目标人物参加的一对一专访；
- 目标人物参加的多人对谈或圆桌；
- 以谈话为主体的完整视频、音频或逐字底稿；
- 来源由采访方、节目制作方、活动主办方或目标人物官方发布。

## 什么不收录

- 新闻转载、二手整理和第三方复述；
- 精华片段、短视频切片、预告和摘要；
- 只有零散引语的报道；
- 演讲、广告、纯纪录片旁白；
- 新闻发布会、业绩会、股东会；
- 只有公司其他高管发言、目标人物没有参加的内容。

以上内容可以在检索过程中充当线索，但不进入最终访谈清单。

## 每场访谈保存什么

数据保存在 `data/interviews.json`。字段刻意控制得很少：

| 字段 | 含义 |
| --- | --- |
| `id` | 这场访谈的唯一编号；同一场访谈永远沿用同一个编号 |
| `person` | 目标人物 |
| `title` | 访谈标题 |
| `program` | 节目、播客或栏目名称 |
| `interview_type` | `one_on_one` 或 `group_conversation` |
| `interviewers` | 采访者或主持人 |
| `published_date` | 首次公开发布日期 |
| `event_date` | 实际录制或发生日期；不知道时填 `null` |
| `source` | 唯一保留的完整一手来源 |
| `topics` | 主要话题，方便以后生成报告 |

`source` 只允许是完整底稿、完整视频或完整音频，并必须标明原始发布者。

## 当前协作方式

1. 找到一个候选内容；
2. 先判断它是不是完整、一手、谈话型内容；
3. 再搜索清单，判断是不是已经存在的同一场访谈；
4. 是新访谈才新增记录；是同一场则只在来源更好时替换原来源；
5. 运行 `npm run validate` 检查格式和明显重复。

当前的三个王宁样本用于验证规则，不代表王宁清单已经检索完成。
